## 1. 设计目标与原则

| 原则 | 落地方式 |
|------|---------|
| 对齐需求基线 | 六路径、掌握度、AI 降级、四端一致性全部有对应设计承载 |
| 单体适度 | 后端为 **2 个 Spring Boot 模块**（非微服务）；模块内分层清晰，未来可拆 |
| 类型安全贯通 | 后端 DTO 契约 ↔ `packages/api-client` ↔ 四端 TS 类型共享 |
| 第三方可降级 | 短信/微信/LLM 全部 Provider 抽象 + 配置开关，缺省隐藏功能而非报错 |
| 可测试 | 判分、掌握度、解锁、间隔重复为**纯函数式核心**，不依赖 Web 上下文 |

### 2.1 为什么是「两模块单体」而非微服务

- 需求一期体量（四端一套后端）单体足够，运维成本最低；
- 两模块按 **受众域** 切分（学员/管理），天然隔离权限与发布节奏；
- 领域服务（判分/掌握度/路径）写成无状态组件，未来若流量需要可平滑拆出。

## 4. 后端分层设计

### 4.1 包结构（两模块同构）

```
com.learnmath.{app|admin}
├── LearnXxxApiApplication.java
├── controller/            # REST，只做参数校验与编排
│   └── vo/  dto/          # 出参/入参
├── service/               # 业务编排（事务边界）
│   ├── domain/            # ★ 领域纯逻辑：judge / mastery / unlock / srs（无 Spring 依赖可单测）
│   └── provider/          # 外部服务抽象：LLM / SMS / WeChat（接口 + 默认实现 + Noop 实现）
├── mapper/                # MyBatis 接口 + XML/注解
├── entity/                # 表映射对象
├── config/                # Security、Redis、Jackson、SSE、OpenAPI、定时任务
├── common/                # 统一响应、错误码、全局异常、上下文（UserContext）、注解
└── infra/                 # AOP 审计日志、限流拦截器、任务（job）
```

### 4.2 统一约定

- **响应体**：`{ code: 0, message: "ok", data: ... }`；分页 `{ code, data: { items, total, page, size } }`
- **错误码分段**（全量表见 04-接口设计 §3）：

| 段 | 含义 | 例 |
|----|------|-----|
| 0 | 成功 | — |
| 1xxx | 参数/请求 | 1001 参数校验失败 |
| 2xxx | 认证/授权 | 2001 未登录、2003 Token 过期、2004 管理域越权 |
| 3xxx | 业务 | **3100 AI 未启用**、**3200 第三方服务未配置**、3301 内容审核不通过、3401 前置未解锁 |
| 5xxx | 系统 | 5000 内部错误、5003 限流 |

- **校验**：`@Validated` + Bean Validation；**审计**：管理端写操作 AOP 落 `admin_op_log`。

### 4.3 认证授权（双域 JWT）

| 项 | 学员域（app） | 管理域（admin） |
|----|--------------|----------------|
| 签发 | learn-app-api | learn-admin-api |
| Secret | 独立 HS256 密钥（环境变量） | 独立密钥，**绝不共用** |
| Access | 2h（内存/前端） | 2h |
| Refresh | 14d，Redis 存 jti 白名单，可踢人下线 | 8h，Redis 白名单 |
| 附加 | 登录渠道、段位等放 claims 最小集 | 仅 adminId + 角色 |
| 限流 | 验证码/短信 Redis 计数（见 §8） | 登录失败 5 次锁 10 分钟 |

### 4.4 缓存与 Redis 用途

| 用途 | 结构 | TTL |
|------|------|-----|
| 验证码 | string | 5min |
| Refresh 会话 | string(jti) | 随 refresh |

| 日/周榜单 | zset | 7d |
| 各类限流计数 | string 自增 | 窗口长 |

## 5. 核心领域设计（★ 本项目的设计难点）

### 5.1 知识图谱 DAG 与无环校验

- 存储：`knowledge_node`（树：parent_id）+ `knowledge_edge`（依赖边：from→to，语义「from 是 to 的前置」）。
- **加边校验**：DFS 从 `to` 反查是否可达 `from`，命中即成环 → 拒绝（错误码 3310 图谱成环）。节点数 <5000，全量子树校验即可，管理端低频操作不做增量优化。
- **后继枚举**：解锁、推荐、图谱着色都依赖「某节点的前置集合」——`knowledge_edge` 建 `(from_id)` 与 `(to_id)` 双索引，进程内 Guava 风格 loading cache（10min）加速，边变更时失效。
- 子树聚焦：以某节点为根的 DFS 导出前端子图。

### 5.2 掌握度模型（跨路径统一指标）

每 (user, node) 存 0-100：

```
score = clamp( base × difficultyFactor − decay , 0, 100 )

base       = Σ(w_i × correct_i) / Σw_i        # 近 20 次作答，w = 2^((i−n)/n) 时间序加权（新题权重大）
difficultyFactor = 1 + 0.05 × (avgDifficulty − 3)   # 做对难题加分，L1~L5 → avg 1..5
decay      = max(0, (天数_since_last − 14) × 1.5)    # 14 天免衰减，之后线性回落
```

- **事件更新**：每次判分后同步重算该 node（单用户单知识点查询量小，直接算）；
- **批量修正**：每日定时任务对 30 天未碰的知识点补衰减；
- 落库 `mastery`，读走 Redis hash 缓存；
- 特殊规则：解答题自评"不会"按 0 分计入；AI 生成题同样计入（标记 `source=ai`，权重 ×0.8 防刷）。

### 5.3 六路径统一引擎

```
learning_path (code: P1..P6, config JSON)
   └── path_node (ref_type → lesson | quiz | paper | assessment | ai | topic | boss, unlock_rule JSON)
         └── user_path_progress (current_node, status, star)
```

**解锁规则 DSL**（`unlock_rule` JSON，求值器在 `service/domain/UnlockRuleEvaluator`）：

```json
{"type":"sequential"}                                    // P1 线性：前一节点完成
{"type":"mastery","nodeId":12,"gte":80}                 // P2/P4：掌握度门槛
{"type":"ladder","nodeId":12,"difficulty":3,"passRate":0.8,"minCount":10}  // P4 阶梯晋级
{"type":"stars","total":10}                              // P6 星数累计
{"type":"paper_pass","paperId":5,"gteScore":60}          // Boss/晋级战
{"type":"allOf":[ ... ],"anyOf":[ ... ]}                 // 组合（与/或嵌套一层）
```

- P1 = sequential + 随堂练；P2 = 图谱浏览无锁（可配置越级）；P3 = 计划任务序列 + mastery 动态调档；P4 = ladder；P5 = 专题节点（顺序+可选 mastery）；P6 = stars + paper_pass。
- 任一路径作答 → 统一事件总线（同进程内 `ApplicationEventPublisher`）→ 更新 mastery/wrong_book/stat_daily/积分/成就。

### 5.4 判分引擎（客观题自动判分）

`service/domain/JudgeService` 纯函数，输入 (question, userAnswer) → (correct, detail)：

| 题型 | 规则 |
|------|------|
| 单选/多选/判断 | 集合相等（多选顺序无关） |
| 填空 | 逐空归一化后比较，支持 `|` 分隔多可接受答案 |
| 解答题 | 不判分 → 进入自评态（对照解析 selfAssess: 会/半会/不会） |

**判分时机（01-D2）**：练习 mode 每题提交即调用 JudgeService 返回结果（`POST /attempts/{id}/answer` 响应含判分）；考试 mode 提交仅暂存，`POST /attempts/{id}/submit` 时统一批量判分。错题入本在"判分发生时"同步执行。

**过程分口径（01-K11 / 评估 P1-6 定死）**：应用五步的过程分（①读题标注 ②设元 ③列模型）**独立展示、不计入 attempt 总分**；attempt 总分 = ④求解判分（客观规则同 §5.4）；⑤回代不计分、仅留痕入能力画像。

**归一化流水线**（可按题配置开关）：trim → 全角转半角 → 去千分位/货币符 → 小写字母化（仅英文题）→ 分数等价（`1/2`≡`0.5`≡`½`）→ 代数等价（二期：CAS）→ 数值容差（`1.00`≡`1`，相对误差 1e-6）。用例见 07 §4.1。

### 5.5 间隔重复（P4 每日一练）

简化 SM-2：

```
EF 初始 2.3；答对：EF' = max(1.3, EF + 0.1)，interval: 1d → 3d → 7d → interval×EF
答错：interval 重置 1d、EF−0.2、进错题本、掌握度按§5.2 重算
抽题：每日取 due（due_date ≤ today）题不足时，从薄弱知识点补齐到 5~10 题
```

### 5.6 测评与计划（P3）

- 自适应测评：分档题库（config 定义档位与升降规则：连续正确升档/错 2 降档），终止条件 = 定档或答满；产出 `assessment_record`（分维度得分 + 定级 L1-L5 + 推荐起点 node）。
- 计划生成：**规则引擎为默认实现**（测评画像 → 按图谱拓扑排序取子集 → 按每日时长目标切成 `plan_task`）；LLM 配置开启后走 `AiProvider.generatePlan`（JSON Schema 约束输出，校验后落库），失败自动回落规则引擎。
- 动态调整：连续 3 天完成 → 下周难度/量 +1 档；连续 3 天未完成 → 插入先修复测。

### 5.7 积分/成就/段位（事件化）

领域事件：`QuestionDone` `CheckInDone` `LevelPassed` `PaperPassed` `PostLiked` `PlanDone`…
监听器：积分账本（`point_transaction` 流水、禁止直接改余额字段）→ 成就规则求值器（规则在 `achievement.rule_json`，解释执行）→ 段位按周积分结算（每周一定时任务）。

**积分定价与风控默认值（评估 P1-2，全部 config 可调）**：

| 项 | 默认值 |
|----|--------|
| 做题判对 | +1 分/题，**日上限 50**（防刷） |
| 每日打卡 | +5；连续 7 天额外 +20；补签 −20 |
| 每日任务完成 | +5~15（task 配置） |
| 挑战赛/晋级 | 赛事配置（如参与 +10、Top3 +100/60/30） |
| 社区被赞 | +2/次（日上限 20）；采纳 +10 |
| **AI 消耗** | 对话 **−5/次（每日前 3 次免费）**；AI 出题 −10/次；讲解 −5/次；余额不足 → 3101 引导做任务 |
| 通胀控制 | 单用户单日获取上限 200；负分不可低于 0（管理员调整除外） |

**赛季（评估 P1-3）**：`season` = 自然月（如 `2026-10`）；每月首周一 04:00 结算上月段位 → 历史赛季数据归档只读（`stage_rank.season` 快照 + `stat_daily` 留存），排行榜按当前赛季展示。

### 5.8 AI 接入层

```
AiFacade (feature: chat|explain|quiz|plan|diagnose)
   ├─ FeatureToggle 来自 config 表 → 关闭即抛 3100
   ├─ RateLimiter: Redis 每日次数（config）+ 积分扣减
   ├─ AiProvider 接口 ─► OpenAICompatProvider (baseUrl/key/model 可配，SSE 流式)
   │                     └ NoopProvider (未配置时，理论不可达——开关先拦)
   ├─ PromptTemplate (config 表管理，含数学人设/中文输出约束/JSON 输出约束)
   └─ AiTask 落库：type、tokens、耗时、关联对象 → 管理端用量报表
```

- SSE：`SseEmitter`，事件 `delta`（增量文本）/ `done`（附 usage）/ `error`（3100/5003/5000）；前端 `EventSource` 或 fetch stream。
- AI 出题结果转换为 `question`（`source=ai`，仅本人可见 + 临时题不进公共库，答后可"入库"转正——一期简化为直接复用生成题结构存 `ai_task.payload`）。

### 5.9 社区内容安全状态机

```
发布 → (敏感词实时扫描) ─┬─ 未命中 → published（先发后审）
                        └─ 命中 → pending_review（扣留，提示“审核中”）
published →(抽审/举报)→ removed / rejected        举报 → report_record → 管理员处理
```

- 敏感词：词库表 + 内存 AC 自动机，启动加载、配置变更时刷新；匹配粒度：正文/标题/昵称。
- 富文本：后端 HTML 白名单清洗（标签/属性白名单，禁 script/事件/on*），前端渲染再兜一层。

## 6. 安全设计

| 项 | 方案 |
|----|------|
| 密码 | BCrypt strength=10；登录/改密/找回全走同一校验 |
| Token | 双域独立密钥；refresh jti 白名单可吊销；管理端 30 天强制重登 |
| 越权 | 学员接口按 `userId` 注入（禁止信任 body 里的 uid）；管理接口角色注解 |
| 限流 | 注解式 `@RateLimit(scene, limit, window)` → Redis 计数器；覆盖验证码、登录、AI、投稿、搜索 |
| 注入/XSS | MyBatis 参数化；富文本双端清洗；输出统一编码 |
| CORS | 显式白名单（按端域名配置），管理域更严 |
| 审计 | 管理端全部写操作 → `admin_op_log`（AOP + 可查） |
| 敏感配置 | Key 全走环境变量/`application-prod.yml`（gitignore），仓库只留 `.env.example` |
| **内容安全 Provider（01 §9 / P0-2）** | 接口抽象 `ContentSecurityProvider`：`WechatMsgSecCheckProvider`（小程序）/ `CloudAuditProvider`（预留）/ `SelfBuiltProvider`（敏感词 AC 自动机，默认）；config 开关切换，未配置三方走自建底线；上架审核前启用对应平台能力 |
| 合规数据动作 | 注销冷静期任务（每日扫描到期 → 匿名化）、导出包 7 天清理任务（入 §7 定时表） |

## 7. 异步与定时任务（一期用 Spring @Scheduled，不引 MQ）

| 任务 | 频率 | 说明 |
|------|------|------|
| 打卡日结 | 每天 00:05（Asia/Shanghai 固定时区） | 断签判定、任务过期 |
| 掌握度衰减补算 | 每天 03:00 | 30 天未碰知识点补 decay |
| 每日统计 `stat_daily` | 每天 00:20 | 聚合前一日行为 |
| 周报生成 | 周一 06:00 | 产出 `study_report` + 站内信 |
| 段位结算 | 周一 04:00 | 周积分 → 段位升降 |
| 计划提醒 | 每天 09:00 | 未完成任务 → 通知 |
| 榜单快照 | 每 10min | zset 截取缓存 |
| 每日一练预生成 | 每天 00:30 | due 题不足时补抽 |

> cloudstudy 引入了 Kafka/Rabbit，那是 16 微服务的必要性；本项目单体 + 事件总线 + 定时任务足够，避免过度设计。

## 9. 关键设计决策记录（ADR 摘要）

| # | 决策 | 备选 | 理由 |
|---|------|------|------|
| 1 | 两模块单体 | 微服务 | 一期规模不匹配微服务成本；受众域切分保留拆分可能 |
| 2 | 定时任务而非 MQ | Kafka | 单体无跨服务一致性问题；任务均可幂等重跑 |
| 3 | 掌握度统一指标 | 每路径独立进度 | 路径间共享成果是产品核心主张（01 §1.1） |
| 4 | 规则引擎为 AI 兜底 | 纯 LLM | 计划生成必须可降级（01 U-45） |
