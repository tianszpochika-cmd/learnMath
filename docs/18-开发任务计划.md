## 1. 终点定义（Definition of Done）

### 1.1 「本地可测试」的精确口径（全部满足）

```
□ git clone 后按《本地测试手册》（附录 A）逐条执行，零手工修补
□ docker compose：MySQL(13307) + Redis(16380) 健康；61 表迁移一次成功可重放
□ 后端：learn-app-api(8080) / learn-admin-api(8081) /actuator/health 双 200
□ 前端：web(28180) / admin(28181) / official(28182) / uniapp-h5(28183) 四端可访问
□ pnpm toolchain:check + ports:check 全绿（versionDrift=fail）
□ 演示账号可跑通附录 B 的 15 条旅程（=07 的 J1-J15）
```

### 1.2 「功能完善」口径

```
□ 01 §14 验收要点 1-10 全部通过（含三内核、公式馆、合规、内容口径）
□ 09 的 14 条功能链 L0-L13 端到端走通（含异常分支抽测）
□ 04 的 app/admin 接口全部实现且 OpenAPI 可浏览（SSE 3 条可用）
□ 四端 UI 与 4 个原型一致（16/17/15/14 的核心屏逐屏对照）
```

### 1.3 「无缺陷」口径（分级清零标准）

| 级别 | 定义 | 终点要求 |
|------|------|---------|
| **P0** | 崩溃/数据错/资金错（积分）/安全越权/迁移失败 | **= 0** |
| **P1** | 主流程断裂（某链走不通）、合规功能不可用、E2E J 系列红 | **= 0** |
| **P2** | 明显体验瑕疵但有绕行 | **= 0**（或台账登记+需求方书面接受） |
| P3 | 打磨项 | 台账登记即可 |
| 门禁 | `mvn test` 绿 · `pnpm typecheck/lint` 绿 · E2E J1-J15 全绿 · 覆盖率达标（07 §1） | **全满足** |

> **机制承诺**：缺陷台账（GitHub Issues 或 `docs/缺陷台账.md`）全程滚动；每个阶段出口跑「阶段回归包」（§4.3）；不允许"先欠着"进入下一阶段。

## 2. 执行框架

### 2.1 六条并行轨道 + 契约先行

```
Track-A 后端（server：内容域→行为域→路径域→AI）
Track-B Web 学习端（apps/web，按 16 号屏序）
Track-C 管理端（apps/admin，按 17 号屏序）
Track-D 移动端（apps/uniapp，按 15 号屏序）
Track-E 官网（apps/official，按 13/14 号）
Track-F 内容生产（12 号流水线，全程并行，M2 起跑）
同步点：① 每任务开工前读对应设计文档（输入列）
        ② 接口以 04 为准：后端先出 OpenAPI → api-client 生成 → 前端消费（禁口头契约）
        ③ 每阶段末「联调日」：四端连真后端跑该阶段旅程
```

### 2.2 任务编号与 DoD 约定

- `T{里程碑}.{序号}`（如 T4.3 = M4 阶段第 3 任务）；
- **每任务 DoD 三件套**：① 编译/检查过 ② 自测清单勾选（含异常分支）③ 单测/用例按 07 归属提交；
- 估量单位 = **人日**（含 Agent 产出+人工评审；评审不可省）。

## 4. 质量机制（"无缺陷"如何保证）

### 4.1 缺陷生命周期

```
发现（自测/E2E/联调日/验收）→ 登记台账（编号/级别/复现步骤/归属轨）
→ 修复（≤1 工作日修 P0/P1；P2 ≤3 天）→ 回归（复现步骤+关联用例）→ 关闭
红线：阶段出口存在未关闭 P0/P1 = 阻塞出口，不得进入下一阶段
```

## 5. 关键路径与并行建议

```
关键路径：T1.5(ORM) → T2.1(表) → T3.4(判分) → T3.7(掌握度) → T4.2(DSL) → T4.10(深钻) → T4.13(web深钻) → T6.9(全量E2E) → T7(LT)
并行填充：Track-B/C 在 M2 起用 OpenAPI mock 干活（api-client 契约先行）
          Track-F 内容线 M2 起全程并行，M4/M5 的素材（链/四卡/公式）提前一周备料
          Track-D 移动端 M3 起并行（复用 web 已验证的 api-client）
最可能堵点：① T1.5 ORM 兼容（首周必须出结论）② T4 深钻数据量（AI 转译吞吐=12 实验）
            ③ E2E 环境稳定性（每阶段首日先修 runner）
```

**节奏**：每阶段 = 开工评审（读设计）→ 实现+自测 → 联调日 → 回归包 → 出口门禁 → 缺陷清点。阶段间不留暗债。

**估量汇总**：M1 6 + M2 10 + M3 12 + M4 15 + M5 12 + M6 12 + M7 5 ≈ **72 人日**（单人+Agent、含评审；内容线 12 号另按其周节奏并行）。缓冲：P0/P1 修复预留 15%。
