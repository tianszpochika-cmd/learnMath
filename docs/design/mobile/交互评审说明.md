## 1. 本轮要评什么

移动端是用户每天回到数源时使用的学习入口：先看见今天该做的一件事，短时间内完成，随时知道已经保存到哪里、为什么尚不能解锁，以及下一步去哪补。新版把官网的数学品牌气质和 Web 学习端的内容语言带到手机上，同时遵守 15 号文档已确认的 **M1–M6**，保持单手可达、一屏一事和题目阅读优先。

本轮以 S01–S44 的旧版原型和 15 号文档为**信息架构与覆盖基线**。新版 `review-v2.html` 是供评审的本地页面；评审时应分别记录“画面已呈现”“本地动作可演示”“真实业务尚待接入”。旧稿里有按钮并不代表新版已经实现该动作，新版里能点也不代表登录、判分、保存、积分或 AI 已经发生。`apps/uniapp` 是独立的产品实现，其开发状态须以 21 号状态表及代码、测试证据为准。

### 移动端设计的四条主线

1. **任务先于功能**：首页首屏回答“现在做什么、要多久、完成后会怎样”。路径、做题、社区、我的保留稳定位置；次级能力通过任务卡、上下文入口进入。
2. **专注与中断同样重要**：课时、作答、深钻与 AI 都可能被来电、锁屏或切应用打断。界面持续告知当前阶段、服务端确认的保存状态、返回后的恢复入口。
3. **规则在动作前出现**：开考前说明辅助、反馈、时限与计分；锁定、内容筹备、样本不足、自评和客观成绩使用不同文案；不要在操作后才解释限制。
4. **品牌让学习更有辨识度**：蓝紫主色、六路径色和少量几何线条建立连续性；长题干、数学公式、输入区、图表和错误说明保持平静、清晰。动画帮助理解状态，不与阅读竞争。

## 4. 三条必须走通的评审旅程

### A. 新人从官网试做到手机继续

公开公式/题目/知识点 → 带明确目标的登录或注册 → **先恢复原目标** S17 / S19 / S33 → 原试做输入回填，由用户决定是否提交；测评仅作为非阻塞邀请。没有原目标的新用户才按 M3 在三屏引导后先进入 S08，再显示 S03 测评 Sheet。已登录可直接校验权限后进入目标；用户主动先做测评时，从 S28 结束、跳过或退出仍回原目标。目标过期、下架或无权限时解释原因，保留已填内容并给搜索、推荐或复制出口。BR-09 的 intent 白名单、resumeToken、账号绑定与消费确认只能由真实服务端完成；原型只能演示目标提示和返回方向。

### B. 日常学习到错题补救

S08 今日任务 → S13 在学课程 → S14 阅读确认与随堂练 → 达标后下一课，未达标时保留“阅读已记录” → S19 作答 → S21 报告 → S22 错题 → S23 断链 → S15 重走推理或 S17 补先修 → 返回练习。S14 的“读完”“练习达标”“课时完成”“掌握度变化”是四个不同结果，界面不得合成一条无条件庆祝文案。S23 只有最终答案而没有步骤证据时写“尚未定位”；AI 建议写“可能卡在这里，待确认”；补救题展示真实可用数量，0 道也给已发布概念或公式内容。

### C. 受限作答、恢复和下一步计划

S10 / S24 / S25 选择试卷或挑战 → 开考前看时限、辅助、反馈、恢复、计分规则 → S19 逐题输入与服务端保存回执 → S20 答题卡检查未答 → 交卷确认 → S21 客观成绩与自评分区 → S29 查看任务或建议差异 → 用户确认应用。断网时标出最后服务端确认时间并保留同端本地草稿；服务端截止后不收迟到答案。主观题允许“不会/半会/会/暂不评价”，可退出后继续评；纯主观卷应写“本卷无客观成绩”，不能显示 0 分或满分。计划建议只提议修改，版本冲突时列出差异，不静默改用户计划。

## 5. 关键页面的手机专属交互

| 场景 | 可评审的手机设计要求 |
|---|---|
| **首页 S08** | 在最容易触及的位置呈现“继续上次学习”和一个当日主任务；任务卡先显示时长、当前进度和明确动作，再显示辅助统计。打卡成功只反馈服务端确认的连签和积分，不在每次点击时演假奖励。 |
| **课时 S14** | 长篇正文保持段落节奏，公式可横向查看且不截断；阅读确认与随堂练分区，底部主按钮随策略和答题状态变化。返回时保留阅读位置。 |
| **深钻 S15** | 纵向链卡每卡先露出“这一步做了什么”，再展开依据、动机、岔路；预测答案提交后保留错因反馈。顺逆采用上下折叠并保留同色步骤关联；切到 AI 带入当前题与步骤。 |
| **图谱 S16–S17** | 手机首选搜索、领域分组和一跳邻域列表，小图只辅助定位，不在窄屏强塞全景画布。四卡固定为起源、现实原型、能力地图、抽象阶梯，代表题另列。锁定、筹备、无证据、样本不足、薄弱和掌握都应有文字。 |
| **作答 S19–S20** | 题号、剩余时间、保存状态和交卷入口稳定可见；选项有大触控区。填空数学工具条在键盘上方，光标处插入；答题卡 40% 概览与 90% 全览之间切换，标记、未答与当前题不只依靠颜色。 |
| **报告 S21** | 客观得分与解答自评是两栏或两个段落；待自评有明确续评入口；错误回到错题时保留对应题号和原因。成绩动画不能遮住“尚在结算”状态。 |
| **计划 S29** | 月/周切换保持所选日期；任务状态区分待做、已完成、跳过、缺席、改期。客观任务点击勾选只发起服务端校验，建议卡展示修改前后与原因。 |
| **公式 S32–S33** | 条件摘要在首屏，能一键到完整条件与误用边界；符号表给定义域和单位，无单位标“无量纲”。七区可折叠但有数据必须可达，小练只显示当前已发布的题型。 |
| **AI S39** | 60% 题面面板顶部有题目摘要与关闭入口，全屏态保留明确返回；流式输出含暂停/失败/重试和公式渲染稳定态。苏格拉底与直接讲解的当前模式清晰可见。 |

### 视觉与触感

主蓝 `#2F6BFF`、紫色焦点和 P1–P6 路径色延续既有品牌。任务首屏可用少量数理线条、进度环与品牌渐变；题面、解析、表单和长阅读区使用纯净背景。移动端标题、正文和学习控件都用清晰无衬线字，数学公式由专门排版承担；官网的衬线大标题与暗色主题不作为手机学习态的默认规范。主行动通常落在下三分之一，危险/不可用操作有文字说明。正确、错误、待复习、锁定与筹备都用色彩加图标或状态词双重表达。动效只在完成、打卡、晋级等明确事件出现；提供减少动态效果降级。

15 号文档的设计尺寸为 750rpx，目标触控热区至少 88rpx × 88rpx；具体设备要检查状态栏、刘海和底部安全区。底部主按钮、数学工具条、答题卡与 AI 面板互相排斥时，当前任务的输入控件优先，不允许被 Tab、悬浮球或键盘盖住。

## 6. 业务规则如何变成可理解的界面

| 规则 | 必须呈现的状态与文案 | 真实能力边界 |
|---|---|---|
| **BR-01 掌握度** | “尚未测量”“样本不足”“薄弱待练”“已掌握”“前置未达标”“内容筹备中”分开；分数变黄时已获得的解锁仍可进入并提醒复习 | 只用服务端合格客观证据计算，同族 7×24 小时与帮助/曝光排除、样本数、衰减和新解锁门槛由服务端决定 |
| **BR-02 课时完成** | 已读未过随堂练时显示“阅读已记录，完成随堂练后继续”；默认客观题全答且正确率至少 80%；纯阅读课显式标注 | 是否完成、下一课解锁和首次 +10 奖励由服务端确认，练习达标不自动等于掌握度提升 |
| **BR-03 辅助权限** | 开考前讲清各类试卷是否可看公式摘要、推导、深钻、AI；受限中入口禁用并说明原因；交卷后可恢复合法学习入口 | 用途、反馈、辅助策略在开考时由服务端冻结；站内全局 AI、答案、社区和另开练习需同一活动作答权限检查 |
| **BR-04 客观与自评** | 客观分、主观自评和待自评分开；纯主观卷不制造客观分；最终报告更新时注明自评修订 | 自评不能改变客观掌握度、竞技排名或重放奖励；主观应用五步按题分存 |
| **BR-05 断链** | 客观观察、用户自报、AI 建议、尚未定位分别标记；旧链重排后仍展示历史步骤说明；0/1/2 道补救如实显示 | 稳定 stepId、版本和证据快照由服务端保存；AI 不可用仍可手选原因和学习 |
| **BR-06/08 内容可见性** | 概念四卡、公式七区与推理链缺失处写“待补全”，并保留已发布部分；工作稿不出现在学员视图 | 公开与学习端只读审核后的 published_snapshot，不得读取管理工作稿或 AI 草稿 |
| **BR-07 保存与恢复** | 每题保存回执、最后确认时间、离线草稿、冲突两份答案和截止状态可见；离开作答时提示未答题数 | 服务端快照和 revision 为准；本地未同步草稿不能跨设备保证恢复，过期草稿不可补交，交卷幂等 |
| **BR-09 目标恢复** | 登录前后均显示“完成后继续学习：资源名”；过期/下架保留输入并提供出口 | 白名单 intent、随机 token、账号绑定、权限和消费确认只能由服务端完成 |
| **BR-10 计划** | 缺席建议、证据不足、学习建议的原因可读；改动前后对照，经用户确认才应用；冲突有重试与重新审阅入口 | 建议不能直接改掌握度或撤销解锁；apply/undo 必须校验版本和后续学习证据 |
| **BR-11 内容覆盖** | 六路径中的可浏览内容、能力锁定与“内容筹备中”明确区分；无可用题时不给假“立即挑战” | 可用格和题池须按真实审核题族、前置与资源覆盖校验，不以演示数量证明达标 |

## 7. 响应式、键盘和无障碍评审

**宽度与安全区。** 桌面评审框用来切换和观察 S01–S44；在真实手机宽度下应去掉评审目录与外框，让学习界面全屏使用视口。以 390px 左右手机画面检查基础布局，同时检查约 320px 窄机、常见大屏手机、横屏和系统字体放大后的文本换行。五 Tab 名称不能被截断；题干与公式不能横向撑破页面；对比内容在横屏可扩大阅读区。手机框原型的固定尺寸只是画稿容器，不是这些适配已经通过的证据。

**软键盘。** 验证码、搜索、数学填空、笔记、发帖和 AI 输入时保持输入行可见。数学工具条跟随键盘上沿且不覆盖光标、答案和提交按钮；键盘收起后恢复底部安全区。确认弹层打开时将焦点移入，关闭后回到触发按钮；无输入时不自动弹键盘干扰阅读。

**手势与等价入口。** 左滑返回、下拉刷新、底部面板拖拽可以提速，但每项都有可见按钮替代；答题卡关闭和交卷必须能明确点击。悬浮球可吸边并避让答题区，不应挡住题目、工具条或下一题。所有可点区域达到触控热区要求，连续危险动作要有足够间隔。

**读屏与低视力。** 图标按钮提供可读名称；数字进度附文字（例如“第 3 题，共 10 题”）；图表给数据摘要；正确/错误有文字与图标；弹层有标题，焦点不落到遮罩后页面；状态更新按优先级宣读。文字放大到 200% 时仍能完成主流程。对比度、真实屏幕阅读器、键盘焦点和减少动态效果都须在运行环境中复核，静态原型不能代替测试。

**多端落地。** H5 的自绘 Tab 与小程序/App 的原生 Tab 要保持同一顺序和语义；微信、支付宝、抖音等渠道能力未配置时隐藏相关登录或分享入口。振动、推送、分享和流式 AI 均允许平台降级，降级时用文字与显式结果反馈，不让用户误以为动作失败或成功。
