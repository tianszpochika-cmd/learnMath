## 1. 范围与定位

本稿把已完成的官网视觉语言延展到 **Web 深度学习场**，供页面结构、视觉一致性、操作顺序与状态文案评审。本轮聚焦十个视图：登录、学习首页、课时、深钻、图谱、作答、报告、错题本、计划、公式。它覆盖从进入学习到完成练习、看懂错误并安排下一步的主链，不代表 Web 端全部功能已经设计或开发完毕。

[旧版十八屏原型](./index.html)仍是 16 号文档中 W01–W18 页面广度的参考；新版十屏用于审查官网风格如何落在高频学习流程。`apps/web` 中已有的 Vue 页面是另一份实现工作，本地 HTML 交互稿与其数据、接口、路由和完成状态彼此独立。

## 2. 本轮视觉决策

16 号文档原 WD2 将官网的衬线、暗色和网格纹理排除在学习端之外。本轮按需求方“按照此版风格制作 Web 学习端”的要求，**调整的是本评审稿的视觉方向**；正式采用时，应同步更新 14、16 号设计决策与共用组件规范。

| 元素 | 新版 Web 学习端用法 | 学习场景约束 |
| --- | --- | --- |
| 品牌与色彩 | 沿用数源标识、蓝紫重点色、六路径语义色，以及官网的克制留白 | 渐变集中在主行动和少量进度焦点，不铺满题面或长篇正文 |
| 字体 | **衬线仅用于页面级标题**；正文、题干说明、表单、按钮、答题卡、图谱标签和工具控件使用清晰的无衬线字 | 公式保持独立数学排版；做题时优先保证扫描效率和字形辨识 |
| 纹理 | 细坐标网格只出现在品牌区或首页欢迎区 | 深钻链、图谱、课时正文和作答画布使用平静的纯色底，避免干扰内容 |
| 主题 | 亮色与暗色双主题同轮设计 | 状态色需在两主题下可读；锁定、正误、证据不足等状态同时配文字或图标 |
| 工作台 | 保留顶部导航、宽画布和任务导向布局 | 深钻、图谱与作答继续保留 16 号文档规定的信息密度和并排对照能力 |

窄屏评审须检查答题卡、深钻依据栏及图谱节点详情如何收起和恢复；键盘焦点、Esc 关闭、输入框内不劫持快捷键，以及减少动态效果时的表现也应纳入视觉复核。这些是交互设计要求，不能以静态画面视为已通过无障碍验收。

## 3. 十屏的职责与连接

| 视图 | 用户要完成的事 | 本轮重点状态与出口 |
| --- | --- | --- |
| 登录 | 从官网或站内入口进入学习，知道登录后去哪里 | 协议确认、可用登录方式、原资源目标提示；完成后回目标或进入首页 |
| 学习首页 | 找到今天最值得做的一步 | 今日任务、在学课时、复习入口、最近作答；进入课时或继续自评 |
| 课时 | 阅读概念并通过随堂练 | 阅读确认、练习进度、未达标提示、下一课门槛；可去深钻或图谱补先修 |
| 深钻 | 理解一道题或一个公式的推理依据 | 通读、预测、顺逆、多解和可用时的 AI 追问；选步联动依据、动机、岔路 |
| 图谱 | 找到知识点的前置关系与下一步学习入口 | 领域定位、掌握证据、四卡、锁定与内容筹备的不同提示；进入课时、公式或练习 |
| 作答 | 在既定规则下完成练习或试卷 | 开始前规则、题目与答题卡、保存状态、时限、交卷确认；提交后进入报告 |
| 报告 | 看清客观成绩、自评与后续行动 | 客观分、自评待办、知识点与错题入口；继续自评或去错题本 |
| 错题本 | 分辨卡点证据并完成补救 | 到期重练、断链来源、尚未定位与可用补救；进入深钻、图谱或重练 |
| 计划 | 确认当前任务和系统提出的调整 | 日历、任务状态、建议差异、确认、冲突和撤销；返回对应学习内容 |
| 公式 | 核对公式成立条件并理解来历与应用 | 条件醒目呈现、符号表、推导、边界、应用等七区；进入公式深钻或对应练习 |

### 三条评审旅程

1. **从官网继续学习**：官网公开词条或公式 → 登录页显示“完成后继续学习此内容” → 登录后回原知识点或公式。若用户选择先测评，跳过、完成或退出测评后仍应回目标；原试做输入只回填，不自动提交。
2. **日常学习与纠错**：首页今日任务 → 课时阅读确认与随堂练 → 作答反馈或报告 → 错题本区分卡点来源 → 深钻选步理解 → 图谱补先修 → 回到复习。每次完成和能力变化都应根据真实证据分别表达。
3. **考试与下一步计划**：开考规则 → 作答保存与交卷 → 报告中的客观分及独立自评 → 计划页查看建议改动 → 用户确认后调整任务。中断、离线、截止和版本冲突都需要明确的恢复或解释入口。

## 4. 业务状态和文案边界

| 规则 | 设计稿应表达的状态 | 正式实现仍需验证的能力 |
| --- | --- | --- |
| **BR-01 掌握度与解锁** | “尚未测量”“样本不足”“待复习”“前置锁定”“内容筹备中”分开呈现；自评不混入客观掌握度 | 仅服务端已判客观题且符合曝光、同族和辅助规则的证据计分；新 mastery 解锁需分数与样本同时达标，已解锁节点不因遗忘重新锁定 |
| **BR-02 课时完成** | “阅读已记录”和“课时已完成”分开；默认随堂练未达标时给补练入口，不显示下一课已解锁 | 默认练习门槛为客观题全答且正确率至少 80%；纯阅读课须明确配置；完成奖励只结算首次 |
| **BR-03 作答与辅助** | 练习可逐题反馈；考试、测评和挑战在交卷前隐藏答案及受限辅助；开考前列清时限、反馈、恢复与计分规则 | 作答策略由服务端冻结，并对全局 AI、答案、深钻、关联问答和另开练习实施同一活动作答权限检查 |
| **BR-04 自评与结算** | 客观成绩与解答题自评独立展示；纯解答卷写“本卷无客观成绩”；自评提供不会、半会、会、暂不评价及退出续评 | 修改自评生成报告修订，但不重放客观判分、积分、错题或排名事件 |
| **BR-05 断链补救** | 区分客观预测记录、用户自报、AI 建议待确认、尚未定位；补救题不足时展示真实数量 | 保留解法、链版本及稳定步骤引用；AI 不可用时仍能提交错题和选择普通补救 |
| **BR-07 作答恢复** | 逐题保存、同步时间、离线状态和冲突选择都应可见；倒计时以服务端截止为准 | 服务端草稿为准；未同步本地草稿只在同端可恢复；到期后不接收迟到答案，重复交卷幂等返回报告 |
| **BR-09 目标恢复** | 登录前后让用户看清原目标；目标过期或下架时解释原因并保留输入 | 使用白名单意图与 resumeToken 兑换；`from` 仅做来源归因，不当成跳转目标 |
| **BR-10 计划建议** | 连续 3 个到期日缺席才触发减量或改期建议；显示改动前后与原因，需确认；冲突和撤销有独立反馈 | 学习证据不足时不推断能力下降；应用建议按计划版本校验，不能静默覆盖用户手动安排 |

图谱四卡固定为**起源、现实原型、能力地图、抽象阶梯**，代表题另列；公式详情需保留**起源、符号表、推导链、成立条件与边界、应用、家族、变形**七区，条件摘要不能代替完整边界。题目深钻与公式深钻使用不同资源类型。未审核或未发布内容、题量不足、AI 未配置，都应有诚实的缺省状态。

图谱状态配色遵守 BR-01：无证据与不足 5 条的样本都用灰色，并通过文字区分；足够证据但分数低于 80 用黄色，达到 80 用绿色；前置锁定用红色锁标识；内容筹备使用独立标记。模式切换仅用于开考前的本地演示，一旦考试题被选择，评审切屏与站内学习辅助也会受限到交卷。正式产品仍须由服务端冻结和检查作答策略。

## 5. 原型真实性与评审结论边界

新版是**本地交互演示**：页面中的姓名、任务、进度、成绩、题目、倒计时、掌握度、错题、计划建议、公式内容及 AI 文案均为设计示例。原型不连接真实账号、内容发布、判分、草稿、计划版本、积分、权限或 AI 服务；点击反馈只证明交互意图可被展示，不证明业务规则已经由服务端落实。

评审时可分别记录：视觉是否与官网同属一个品牌、十屏的入口与返回是否清楚、状态文案是否符合上表、桌面及窄屏的阅读和操作是否顺畅。浏览器中的实际视觉复核与操作检查**尚待完成**；本说明和单文件原型不能作为 `apps/web` 的开发完成、接口联调、业务验收或上线依据。

后续开发应以 01/09/16/20 号文档的现行规则核对页面与接口，并将本轮确认的视觉调整回写设计规范；其余八个旧原型视图仍需按同一套新视觉继续评审。
