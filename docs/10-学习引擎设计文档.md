## 1. 设计哲学（产品内核重定位）

> **让用户盯住一道题，看透「每一步为什么这样推、还能怎样推」；让每个概念回到它诞生的现实问题。**
> 数学不是符号操演，是**可追溯的推理**与**可感知的世界**。

| 支柱 | 含义 | 对应内核 |
|------|------|---------|
| 推理可追溯 | 复杂题 = 大量逻辑耦合；每步必须能回答"凭什么合法"与"为什么想到" | 内核一（§2） |
| 推理可比较 | 同一题存在多条链（顺推/逆推/多解），比较中掌握通法 | 内核一（§2.4） |
| 概念有来历 | Why before How：先有现实问题，才有数学概念 | 内核二（§3） |
| 抽象有回路 | 应用题 = 现实⇄抽象的双向翻译，解要回到现实 | 内核二（§3.2） |

## 2. 内核一：推理链解剖（题目作为逻辑耦合体）

### 2.1 对象模型

```
question（题）
 └─ solution_path 解法（一题多解：解法A/B/C…）
     ├ kind: 通法 | 技巧法 | 另解   view: 综合法(顺推) | 分析法(逆推) | 并列
     └ reasoning_step 推理步
         ├ seq          步序
         ├ step_type    读条件|目标转化|等价变形|放缩(标方向)|构造|论证|回代检验|工具选择
         ├ content      本步内容（做了什么，Markdown+LaTeX）
         ├ warrant      【凭什么合法】依据正文 + node_refs[] 挂回知识图谱
         ├ motive       【为什么想到】信号识别/目标倒推/直觉/试错排除
         ├ off_ramp     【岔路】常见错误 & 为什么别的直觉走不通
         └ edge_from[]  依赖的前置步（DAG；一步可依赖多步/多条件 → 耦合可视）
     └─ step_prediction 预测题（E2 引导模式用）
         ├ mode: 选步型 | 选依据 | 填动机 | 简答
         ├ options[] / answer / explain(点评：你会这么想因为…但…因为…)
```

**step_type 枚举即"推理能力维度"**（§2.5 画像的数据源）。

### 2.2 一道链的完整示例（河宽测量 · 三角函数应用）

| 步 | type | content | warrant（凭什么） | motive（为什么想到） | off_ramp（岔路） |
|----|------|---------|------------------|---------------------|------------------|
| 1 | 构造 | 不可达点 C 画成 △ABC | 建模：现实→几何 | **测不了就画出来**（古埃及测河宽原型） | 硬量不可达；相似法缺比例数据 |
| 2 | 工具选择 | 用正弦定理 | 正弦定理适用型：边角组合匹配 | **看信号**：题给的是角+边的组合 | 余弦需三边/夹角，数据凑不齐 |
| 3 | 等价变形 | 两边同除 sinC 解 c | 等价变换；前置校验 sinC≠0（C 为内角） | 逆推：要 c 就孤立 c | 不校验除式为零 |
| 4 | 回代检验 | c≈85m，回答河宽 | 单位/量级合理性 | 解必须**回到现实**回答问题 | 忘单位；数量级荒谬不自检 |

- **耦合度**：本题 cross 三角函数/建模/方程求解 3 个知识域 → `question.coupling_degree=3`；
  `reasoning_steps=4`、`needs_construction=1`。→ *难 = 耦合多，不只是算得多*（01 新难度观）。

### 2.3 一题五玩（交互模式规格）

| # | 模式 | 规格 | 决策 |
|---|------|------|------|
| ① | **通读** | 全链画布（步骤节点+依赖边），点步开三层抽屉（依据/动机/岔路），可折叠 | 默认态 |
| ② | **引导预测** | 逐步隐藏 → 提交预测 → 揭示 + **点评双分支**（对：强化动机；错："你会这么想因为…但…因为…"）。步间可跳过；进度可中断续玩 | **E2：可选开启，首次做题强制教学一次** |
| ③ | **顺逆对照** | 综合法链 ⇄ 分析法链并排，同色对齐同一步；点击联动高亮 | 核心：直答"为什么这样推" |
| ④ | **多解画廊** | 解法 tab 切换 + 对比表（步数/技巧性/计算量/适用范围）+ **"本题通法"总结卡** | 直答"有没有别的方法" |
| ⑤ | **AI 苏格拉底** | 沿当前链追问（"这步为什么可以？""条件换成 XX 还成立吗？"），默认不吐完整答案 | **E5：默认此模式，一键切直接讲解** |

深钻页 = 五玩合一：`/deepdive/:questionId`（05 §9）。任何路径（随堂练/阶梯/考试/专题）的题面均可一键进深钻；考试模式中**作答完成/交卷后**才开放（防作弊）。

### 2.4 推理链的挂载范围（与六路径的关系）

深钻是**跨路径能力**，不新增第七路径：

| 场景 | 深钻可用性 |
|------|-----------|
| P1 随堂练错题、P4 阶梯、P5 专题例题 | 随时可进 |
| 考试卷/挑战赛 | 交卷判分后开放 |
| 错题本 | **一键深钻**（配合 §2.5 断链） |
| 概念页例题 | 内嵌链视图（简版） |

### 2.5 评价升级：错，要错在"链"上

1. **断链定位**：错题本升级 —— 作答错误时（有链题）记录 `broken_step_seq` + `break_kind`（缺依据/缺动机/变形错误/漏检验），来源：
   - 用户在深钻预测中答错的步 → 自动入链；
   - 普通作答错 → AI 结合用户答案与链推断断点（E1 转译题有链才可用；无链题退回传统错因标签）。
2. **补救直达**：错题本条目 → 「补哪里」= 断步的 `warrant.node_refs` 图谱节点 + 该步 `motive` 训练（推荐同类预测题 2 道）。
3. **推理能力画像**：按 `step_type` 统计用户强弱（读条件/选工具/等价变形/回代检验…），进周报与统计页雷达的第二张图。

### 2.6 题库分层生产（E1）

| 层 | 覆盖 | 生产方式 | 标注 |
|----|------|---------|------|
| **L-精** | 精选题（每知识点 3-5 道代表题）、晋级战/Boss 卷、示范专题 | **人工链编辑器精修**（管理端 §5.2），双人校对 | `chain_quality=curated` |
| **L-AI** | 普通题、批量导入题 | **AI 链转译器**：解析/答案 → 结构化链草稿 → 管理端抽检队列 | `chain_quality=ai_draft`（学员端展示角标"AI 整理"） |
| **L-断** | 用户错题 | 断链自动产生（§2.5） | 仅本人可见 |

**AI 链转译规格**：
- 输入：stem/options/answer/analysis + 图谱节点标签；
- 输出：JSON（solution_path[]×reasoning_step[]，schema 强约束：每步必须含 type/content/warrant/motive，off_ramp 可空）；
- 校验：步数 ≥2、seq 连续、warrant 必引用给定节点或"等价变换"内置白名单 → 失败重试 2 次 → 仍败入人工队列；
- 成本控制：仅在管理端"批量转译"任务触发，不面向 C 端实时；用量入 AI 报表（04 admin /ai/usage）。

## 3. 内核二：动机先行与现实回链

### 3.1 概念四卡（concept_narrative）

每个知识点节点可挂一张叙事卡，概念页**先卡后定义**（tab 序：起源→现实→能力→抽象→正式定义）：

| 卡 | 内容规范 | 示例（三角函数） |
|----|---------|------------------|
| ① 起源 | 谁/何时/被什么现实问题逼出来；关键历史节点 | 天文测角与土地测量 → 弦表 → 函数化；"trigonon+metron = 测量术" |
| ② 现实原型 | 自然/生活中的原生形态（≥3 个具体例子） | 影长/斜坡/圆周运动 → 声光波/四季/心跳——正弦长在自然里 |
| ③ 能力（应用地图） | 能解哪类现实问题 → 关联应用题现实域标签 | 不可达测距｜方位导航｜交流电｜傅里叶分解 |
| ④ 抽象阶梯 | 现实语言→模型→符号，逐级映射标注 | "坡多陡"→对边/邻边→`tanθ` |

- **生产（E3）**：新概念 = AI 草稿 → 管理端审核 → 上架（卡不全打 `narrative_status=draft` 角标，**不卡上架**）；存量渐进补全，管理端有"待补全"清单；
- **钩子**：周报/站内信/推送附「**数学与世界**」一条起源故事（按图谱节点轮换：斐波那契与向日葵、e 与增长、复数与旋转…）；博士级内容同构（如 ε-δ 的"无穷小的官司"）。

### 3.2 应用题 = 建模翻译训练（Translation Chain · 五步）

应用题（`question.kind=applied`，含现实域标签）作答进入专属五步工作台（05 §9）：

| 步 | 交互 | 必答性（**E4**） |
|----|------|-----------------|
| ① 读题标注 | 句段点选分类：量/关系/目标，高亮联动 | 必答（分类可多选，答错可改） |
| ② 抽象设元 | 选/填"设 x 为…" + **追问**：这句生活话对应哪个量？为什么设它？ | 必答 |
| ③ 列模型 | 关系式逐项组装，每项选依据（相等/不等/函数关系） | 必答 |
| ④ 求解 | **复用内核一推理链**（深钻简版内嵌） | 必答（判分同普通题） |
| ⑤ 回代解释 | 结构化输入：现实答案+单位 / 量级是否合理 / 是否回答了问题 | **提醒可跳过，跳过留痕**（`backsolve_skipped` 进统计） |

- 回代留痕进能力画像（"回代检验"step_type 弱项人群 → 报表与周报提示）；
- 判分：①-③ 计入过程分（配置比例），④ 结果判分，⑤ 不计分只留痕（E4）。

### 3.3 双向训练（抽象⇄具体的来回拉扯）

| 方向 | 功能 | 入口 |
|------|------|------|
| 场景 → 题 | 给一段生活材料，用户自己编题（设元+列式），AI 对照参考点评"你抓住了哪些量、漏了什么" | 应用专题页 [编一道题] |
| 题 → 场景 | 给方程/函数，还原成生活叙述（翻译题，客观+自评） | 同上 [翻译回人话] |
| 生成供给 | AI 生成"现实域×知识点"应用题草稿 → 题库（进 E1 的 L-AI 层流程） | 管理端任务 |

### 3.4 现实域标签体系

`tag` 新增一类 `domain`（测量/金融/运动/自然现象/工程/博弈/艺术…）：
- 学员端：「从生活学数学」专题浏览（按域聚合应用题与概念）；
- 官网：对应 SEO 页（"三角函数在生活中的应用"长尾）。

## 4. AI 角色升级（四个新职责）

| 职责 | 模式 | 说明 |
|------|------|------|
| **链转译器** | 管理端批量任务 | E1：解析→结构化链草稿，schema 校验+人工抽检 |
| **动机卡生成** | 管理端单节点任务 | E3：起源/现实/能力/抽象四卡草稿，史实类要求给出处提示 |
| **苏格拉底讲解** | C 端默认（E5） | 沿链提问；用户可切"直接讲解"；两模式共享上下文（链 id+当前步） |
| **翻译教练** | C 端应用五步 | ②设元与⑤回代的点评（对 E4 跳过者，下次同类题再温和提醒一次） |

## 6. 数据与接口增量（索引）

**数据库（03 §8 增补 6 表）**：`solution_path`、`reasoning_step`、`step_edge`（并入 step 字段亦可，最终以 03 为准）、`step_prediction`、`concept_narrative`、`translation_pair`；`question` +`kind/coupling_degree/reasoning_steps/needs_construction`；`wrong_book` +`broken_step_seq/break_kind/backsolve_skipped(作答表)`。

**接口（04 §4.13 增补 ≈12 个）**：深钻链查询（含五玩参数）、预测提交与点评、多解对比、顺逆链、断链上报/推断、四卡读取（app）、AI 苏格拉底/直接讲解（SSE 复用）、应用五步提交、编题/翻译练习；admin：链 CRUD、转译任务、四卡 CRUD/审核、翻译题生成。

## 7. 度量（进统计报表）

| 深钻打开率 / 五玩分布 | 精髓功能是否被用 |
