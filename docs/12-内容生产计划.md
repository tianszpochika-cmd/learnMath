## 0. 背景与原则

评估结论：功能承诺（六路径 + 三内核 + 十万题）与生产能力（1 人 + Agent）之间存在结构性缺口。本计划以三条原则闭合：

1. **MVC 先行**：先定义"最小可玩内容集"，让功能开发与内容生产并行，M4 时平台"有得学"而不是"能跑空壳"。
2. **纵向切片，不横向摊饼**：先打穿 **1 个示范域** 的全部路径与三内核，验证内容形态后再复制到其他域。
3. **产能用实验校准**：M2 第一周做真实产能实验，用数据回填里程碑，不拍脑袋估进度。

## 1. MVC —— 最小可玩内容集（M4 退出标准）

**示范域选择：代数主线「数与式 → 方程 → 不等式 → 函数 → 二次函数」**
理由：天然 DAG 前置链清晰、应用题素材丰富（行程/工程/金融）、公式密集（求根/判别/均值）、贯通六路径可行性最高。

| 内容物 | MVC 数量 | 说明 |
|--------|---------|------|
| 知识点节点 | **70** | 覆盖示范域全 DAG，含跨域挂接（几何/概率各挂 1-2 个接口点） |
| 依赖边 | **≥90** | DAG 密度决定图谱与解锁可玩性；全部过无环校验 |
| 课程（P1） | **2 门 × 8-10 课时** | 图文 Markdown+LaTeX 为主，视频外链≤10 条 |
| 题库 | **300 题** | 结构：选择 120 / 填空 90 / 解答 60 / **应用题 30**（五步工作台专用） |
| ├ 精修推理链（curated） | 60 题 | 示范域代表题，人工链编辑器精修（E1 L-精），每题 2 解法优先 |
| └ AI 转译链（ai_draft） | 240 题 | 批量转译 + ≥20% 抽检（E1 L-AI） |
| 试卷 | **6** | 练习卷×2、晋级战×1、Boss×1、每日一练题池×1（80 题）、测评卷×1（P3 分档） |
| 概念四卡 | **20 张** | 示范域核心概念（方程思想、函数、变量与未知、不等式性质…），AI 起草+审核（E3） |
| 公式（tier 1-3） | **80 条** | 含符号表、条件红条、≥1 条推导链/条、错误变形；alias 完整（F1/F2） |
| 专题（P5） | **2 个** | 如「方程建模 30 讲」「二次函数综合」，各 5-8 节点 |
| 六路径骨架 | 全部可走通 | P1 绑 2 门课；P4 阶梯=示范域知识点矩阵；P6 关卡 1 大关 × 8 小关 + Boss；P2/P3/P5 按上表 |
| 应用现实域标签 | 示范域全覆盖 | 行程/工程/金融/浓度/几何测量 ≥5 域各 ≥4 题 |
| 成就/任务配置 | 30 徽章 / 7 日任务模板 | 激励系统可运转 |

**MVC 验收 = 01 §14 验收 2/3/4 在示范域上全绿。**

## 3. 生产流水线（与 E1/E2/E3/F2 对齐）

```
① 素材规划：域×知识点大纲（对齐课标/经典教材目录，只借结构不抄原题）
② 生产分流：
   题库 ── 精修题：人工出题/改写 → 链编辑器精修 → 双校（自检+复检）
        └─ 普通题：AI 生成/原创改写 → 链转译(E1) → 抽检 ≥20% → 上架标 ai_draft
   四卡 ── AI 起草（史实必须附出处）→ 审核 → published（E3）
   公式 ── AI 批量起草 → 推导转译 → 审核 → 上架（F2）；alias 合并治理
   课时 ── Markdown+LaTeX 图文（模板化：动机→定义→例题→随堂练）→ 审核
   专题/路径编排 ── 管理端编排器 → schema 校验 → 发布
③ 质检关卡（§7）→ 上架 → 缓存失效 → 学员端可见
```

**版权红线（强制）**：
- ❌ 不导入任何受版权题库原题（教辅扫描、商业题库 OCR）；
- ✅ 题目来源限于：AI 原创生成、经典模型题**参数化改写**（换数/换情境/反向构造）、自编；
- ✅ 公式/定理/史实本身无版权，但四卡**史实表述需附出处**供审核；
- ✅ 视频仅外链官方/授权来源（01 C-06），平台不存储传播他方视频。

## 4. 产能实验（M2 第一周 · 里程碑校准器）

| 项 | 设计 |
|----|------|
| 样本 | 100 道普通题（含 20 应用题）+ 20 公式 + 10 概念四卡 |
| 动作 | 走完整流水线：AI 起草/转译 → 抽检 → 记录工时 |
| 度量 | ① 链转译一次通过率（目标 ≥70%，否则改 prompt/schema）② 单位吞吐（题/小时·人）③ 错误类型分布（条件错/史实错/LaTeX 错/步骤断）④ 抽检发现率 |
| 输出 | **回填本表 §2 分期目标**（若吞吐低于计划 50% → 砍 v1.0 目标至 1,500 题/2 域并同步 01 §13） |
| 时机 | M2 第 1 周，作为 06-M2 退出标准之一 |

## 5. 角色与节奏

| 角色 | 职责 | 说明 |
|------|------|------|
| Agent 生产线 | 起草、转译、批量导入、编排 | 全部走管理端任务台，可脚本化 |
| 人工（需求方） | 抽检、审核四卡史实、curated 精修终审 | **每周预留固定带宽**（见节奏） |
| 周节奏 | 周一设定域/题集目标 → 周中 Agent 批量生产 → 周五抽检会 → 上架 + 更新 §9 度量看板 | 与 06 里程碑周对齐 |

## 6. 质量门槛

| 关卡 | 规则 |
|------|------|
| 精修链（curated） | 双检：生产者自检 + 第二遍复检（同人隔日亦可）；步数≥2、四要素齐、warrant 挂点正确 |
| AI 链/四卡/公式（ai_draft） | 抽检 ≥20%；**批次错误率 >10% 整批打回** 重跑 prompt |
| 史实类（origin/四卡） | 100% 核出处，无出处的表述改写为非断言口吻 |
| LaTeX | 渲染校验零报错（入库前机器校验） |
| DAG/引用 | 无环、无孤儿、无死链（管理端 validate 全绿） |
| 学员可见性 | 未过审一律 status=待审，C 端不可见（01 可降级原则反向应用） |

## 8. 风险与应对

| 风险 | 应对 |
|------|------|
| 吞吐不及预期 | §4 实验数据触发 §2 目标下调（写死在计划里，避免"功能完内容空"） |
| AI 链质量波动 | prompt 版本化 + 批次错误率红线（§6）+ 人工抽检队列可视化（04 /chain/translate-queue） |
| 版权纠纷 | §3 红线 + 上线前抽样法律自查（重点：应用题情境文字、四卡史实引文） |
| 单一示范域偏科 | M5 起每阶段新增域，M7 覆盖 4 域；域选择由 §9 数据（搜索无结果率）驱动 |
