## 1. 掌握度与解锁（BR-01）

### 1.1 什么算有效学习证据

- `correct_i` 仅取 0 或 1。掌握度只使用服务端已判分的客观题；自评、AI 未审核生成题、看解析后的跟练只进入练习记录或自评画像，不计掌握度或晋级统计。
- 同用户、同 `question_family_id`（无变式族时等于题目 id），滚动 7×24 小时最多取第一条合格提交；包括答错，不能用后续答对覆盖第一次。已判分答案不可修改，重做创建新 attempt。
- 同用户在作答前 24 小时内已获该题同族答案/解析/深钻，或本次使用 AI/完整推导等帮助，标记 `assisted=true`，本次不能成为有效证据。只读题面不算曝光。曝光记录以服务端已返回的内容为准，不能据此声称检测到站外帮助。
- 公开每日题及其同族不得进入测评、晋级战、Boss、挑战赛；发布和开卷时均校验。未知的站外帮助无法检测，产品只提供平台内规则约束，不宣称监考级防作弊。
- 每知识点取最近 20 条有效证据；多知识点题对其全部已审核关联节点记同一次证据，不以标签数量增加积分。保存 question/family/version、answerId、难度、正误、发生时间和排除原因。
- 并发判分按用户学习记录锁串行决定同族首条证据，提交顺序由服务端判分提交时刻和answerId确定，不能并发计入两条。同族身份修改需重新校验公开/曝光范围；历史证据保留当时族ID与版本。
- `n=0`：score=null，显示“尚未测量”；`1≤n<5`：可显示参考分但标“样本不足”，不据此获得 mastery 解锁。自评画像明确另列，不混入客观正确率。
- 图谱颜色优先级：内容筹备独立标记；前置锁定用红色锁标识；无证据/样本不足灰色；有足够样本且score<80为黄色（覆盖0–79.99），score≥80绿色。已得解锁即使变黄仍可进入。

### 1.2 唯一计算公式

```text
i=1..n（旧→新），w_i=2^((i-n)/n)
base=Σ(w_i×correct_i)/Σw_i                   # 0..1
avgDifficulty=Σ(w_i×difficulty_i)/Σw_i       # 1..5
factor=1+0.05×(avgDifficulty-3)               # 0.90..1.10
baseScore=clamp(100×base×factor,0,100)
days=floor((asOf-lastEligibleAt)/(24h))        # 完整经过天数，统一 UTC 时刻计算
decay=max(0,days-14)×1.5
score=roundHalfUp(clamp(baseScore-decay,0,100),2)
```

比较门槛使用同一份两位小数 score；前端不二次计算。每天 03:00（Asia/Shanghai）刷新所有超过 14 天的节点；读取和解锁求值也按当前 asOf 重算，因此不依赖任务准时运行。重算从原始证据的 baseScore 开始，不在已衰减分数上再次减分。缓存带 calculatedAt 和下一个衰减边界，过边界失效。

### 1.3 解锁与复习

- 新的 mastery 解锁要求 score≥80 且有效样本≥5；必须前置边全部满足，推荐边只提示。P4 阶梯独立使用该难度最近 20 条有效证据的未加权正确率≥0.8 且≥10 题。
- 达到阶梯条件只解锁“晋级战”；晋级战客观成绩≥80% 才解锁下一难度。晋级战自身不得以“下一难度已解锁”为前置，避免循环依赖。
- 已获得的路径节点解锁记录持久保存（user_path_progress.unlocked_nodes），不因遗忘或内容规则调整重新锁定；显示复习提醒。新的节点按最新规则求值；内容下架按内容可用性处理，不删除历史进度。
- SRS 连续两次正确要求分属不同自然日的到期、未使用帮助的重练。手动“我已掌握”只改变个人错题整理状态，不更改掌握度、晋级或奖励；移出错题本不删除客观作答证据。

| 样例 | 期望 |
|---|---|
| 5 道不同族 L3 全对，日 0 | 100；可获得 mastery 解锁 |
| 5 道 L1 全对 | 90 |
| 5 道 L3 全错 | 0 |
| 无有效题；只有自评“半会” | null；自评参考值 0.5 独立显示 |
| 1 道 L3 全对 | 100 + 样本不足；不解锁 |
| baseScore=100，第 14/15/30/31 天 | 100 / 98.5 / 76 / 74.5 |
| 同一天读取与批量各算两次 | 与首次计算一致，不重复衰减 |
| 5 个有效样本，score=79.9 / 80 | 新节点拒绝 / 放行 |
| 同族 7 天内连续重做 10 次 | 最多 1 条有效证据，不能达阶梯 minCount |
| 阶梯 8/10 正确；晋级战未做 / 80% | 晋级战可用但下一难度锁定 / 下一难度解锁 |

## 2. 课时完成（BR-02）

`read_completed` 是用户主动确认读完；不把滚动位置或视频时长等同于理解。`lesson_completed` 控制 P1 进度和下一课；`practice_passed` 表示达标，三者分别存储。

- 课时策略 `completion_policy=practice_required` 为默认；题组首次进入课时时冻结该策略和阈值版本。随堂练客观题全部提交且正确率≥80%才达标。解答题自评不充当门槛。
- 纯阅读课时可显式设 `read_only`，必须在管理端发布时确认；无客观题却设 practice_required 的课时拒绝发布。无有效题不允许通过“分母为 0”得到 100%。
- 原文的软完成收敛为 read_only：可先记阅读完成，但未满足当前策略时课时仍在进行、不解锁、不发完成积分。前端显示“阅读已记录，完成随堂练后继续”。
- 重做随堂练可满足课时练习达标，但是否更新掌握度仍按 BR-01 筛选，不能把教学练习达标当作独立能力证明。
- 课时首次完成奖励默认 +10，按 userId+lessonId 唯一业务键发放；配置变更或复习不重复发。完成弹层仅显示真实变化，禁止无条件“掌握度↑”。

| 阅读 | 策略 | 随堂练 | 课时完成 / 下一课 / 完成积分 |
|---|---|---|---|
| 未确认 | 任意 | 任意 | 否 / 不新增解锁 / 0 |
| 已确认 | practice_required | 未答或<80% | 否 / 不新增解锁 / 0 |
| 已确认 | practice_required | 客观题全答且≥80% | 是 / 解锁 / 首次+10 |
| 已确认 | read_only | 无或未达标 | 是 / 解锁 / 首次+10；不代表掌握 |
| 已完成再请求 | 任意 | 任意 | 返回原结果 / 不重复 / 0 |

## 3. 作答模式与辅助矩阵（BR-03）

mode（练习、试卷、每日一练、挑战、随堂、测评、晋级战、Boss）描述用途；`feedback_mode=immediate|on_submit` 和 `assistance_policy=learning|reference_only|restricted|open_book` 分开保存。服务端创建并冻结，客户端不能改。

| 用途 | 默认策略 | 反馈 | 公式条件摘要 | 完整推导/题目深钻 | AI/关联问答 | 成绩用途 |
|---|---|---|---|---|---|---|
| 自由练习/每日一练/随堂/普通关 | learning | 客观逐题 | 可 | 可，记帮助/曝光 | 可，记帮助 | 符合 BR-01 才计掌握度；普通关星级用客观首答 |
| 入学/复测 | restricted | 整体结束后；服务端可逐题调档但不返正误 | 不可 | 不可 | 不可 | 客观定级 |
| 普通考试 | reference_only | 交卷后 | 仅开卷时冻结的允许公式表：式子/符号/条件，无链接 | 不可 | 不可 | 客观分；同策略比较 |
| 晋级战/Boss/挑战赛 | restricted | 交卷后 | 不可 | 不可 | 不可 | 仅审核通过客观题，可用于晋级/星级/榜单 |
| 管理员明确配置的开卷考试 | open_book | 交卷后 | 可 | 公式推导可；本卷题目解析/深钻仍待交卷 | 可，记帮助 | 标“开卷”，不进竞技榜/晋级/掌握度 |

开考页明确列出辅助、时限、恢复与计分规则。一期晋级战/Boss/挑战赛与测评发布时拒绝含解答题、未审核题或已公开同族题；普通考试可以混合题型，客观与自评分开。

同账号一次只能有一个未交卷的 on_submit 作答；并发开启返回 3007 和原作答入口，用户可继续或确认提前交卷。未交卷期间，已认证的全局 AI、题目答案、关联社区、题/公式深钻和另开练习都检查服务端活动作答策略，不能通过漏传 attemptId 绕过。open_book 只放行矩阵中允许项；本卷题目的答案接口仍拒绝提前返回。匿名官网公开内容仍然公开，不冒充能封锁站外或匿名查阅。

当前作答的快照与策略决定权限，不能因历史上曾交过同一道题就提前开放。本次交卷事务提交后解除活动约束；自评阶段已允许看解析。提前结束测评只保留已答记录，不出完整定级，不发通关奖励。

## 4. 自评与结算（BR-04）

attempt 状态：`in_progress → submitted → pending_self_assess → finalized`；无解答题时 submitted 直接 finalized。submitted 为可恢复的判分中状态；任务失败重试只产生一次领域事件。截止时间到或人工交卷都走同一状态机。

- 总成绩对象拆为 `objectiveEarned/objectivePossible/objectiveRate` 和 `selfAssessment`。只有客观题计前者；纯解答卷 rate=null、显示“本卷无客观成绩”，禁止显示 0 分或满分。
- 自评逐题保存 `unrated|cannot|partial|can|skipped`，参考值 null/0/0.5/1/null。页面提供对照解析、“不会/半会/会”、“暂不评价”；首页作答记录及报告的“继续自评”可恢复进度。
- 交卷时已判客观错题立即入本，掌握度/客观成绩及客观作答事件只结算一次。pending 自评不阻塞客观部分，不把未评题当错题或低能力证据。
- 自评 cannot/partial 纳入“自评待巩固”错题分类；can/skipped 不新增错题；均不提高掌握度或竞技排名。用户改评只更新这条作答的自评证据，不能清除其他作答产生的错误记录。
- 所有解答题均已选包括 skipped 时 finalized；已 finalized 的自评可用 revision 更新，生成新的报告版本与自评历史，不重放积分、客观错题计数、成就或排行榜事件。报告始终标自评内容，不制造混合总分。
- 普通关可包含解答学习任务，但星级仅基于客观分和用时；纯解答专题按任务完成给参与徽章，不授客观满分/段位。
- 应用五步按attempt_answer逐题保存（请求含seq/revision/requestId），同卷多道应用题不得共用一份five_steps；过程分仅作各题反馈，不跨题覆盖或加入客观成绩。

## 5. 断链证据与补救（BR-05）

断链不是“有链必然定位”。保存 `status=unlocated|suggested|observed|self_reported`、`source=prediction|user|ai`、`solutionPathId/chainVersion/stepId`、可选 kind 及 `evidenceAnswerId`。只知道最终答案时可 unlocated，AI 建议为 suggested，标“可能卡在这里，待确认”，不显示确定断言。

同一 wrong_book 的 `break_evidence_json` 可保存多条证据（key=evidenceAnswerId+source+stepId）；stepSeq 仅为历史显示值。每条带最小链步骤和 warrant_nodes 快照；链重排或下架后仍显示原解法与步骤说明，当前资源不可用时给同知识点补救，禁止随意跳到新版本同 seq。

- observed（预测题客观答错）用于推理画像；self_reported 独立展示；AI suggested 不参与推理能力分数，用户确认后变为 self_reported，不伪装成客观观察。
- AI 未启用/失败时，普通错题显示“尚未定位”，提供错因标签、选择解法/步骤、自报和同知识点练习；流程不能等待 AI 才提交成功。
- 预测中的“填动机/简答”不能假设能精确自动判对：一期对照参考后自报，不计 observed；客观选步/选依据才产生 observed。
- 补救推荐 2 道题是期望上限，不是凭空保证；不足 2 道展示实际数量，0 道给已发布概念/公式内容和稍后复习，禁止空列表仍显示“开始 2 题”。

## 6. 内容发布与完整度（BR-06）

status 控制工作稿：draft/review/published；completeness 控制内容是否齐全，两者独立。概念卡工作稿字段可编辑，但学员与官网只读 `published_snapshot`，其中有 version、publishedAt、已审核四卡字段与缺失卡名。首次无发布快照时返回空四卡和 missingCards，绝不返回草稿正文。

部分卡审核通过也可以发布一个部分快照，显示“待补全”；修改进入待审不覆盖上次发布快照。审核发布用 expectedRevision 校验并原子替换快照、增加 publishedVersion、失效缓存；撤下内容用明确 unpublish 清除对外快照，不能靠工作稿 status 隐式下线。

此发布快照规则同样用于公式和推理链；quality=ai_draft 只是“AI 整理”的来源质量标签，不等于审核状态，也不赋予可见权限。管理预览接口与公开/学习接口分离并验证管理域权限。

## 7. 作答冻结、保存与恢复（BR-07）

- 开始作答原子创建题目快照（题面/选项/图片资源版本/关联节点/难度/族 id/标准答案/解析/判分规则/分值）及辅助规则快照。标准答案、解析等私密字段只在符合 BR-03 的投影中返回，不能把全量 JSON 直接给前端。资源文件在有关历史记录保存期内保留，不随内容下架物理删除。
- 草稿以服务端为准，逐题保存带 answerRevision 与 requestId；2 秒防抖、换题立即保存。考试草稿不判分；练习显式“提交本题”后才判分，已判题锁定，重做另开。
- 时间以服务端 `deadlineAt=min(startedAt+duration, challengeEndAt)` 为准，无时限练习为 null。`serverNow` 用于客户端倒计时校准。有效提交要求服务端入锁检查的时刻 `< deadlineAt`；等于截止即过期。
- 到期服务端任务或下一次读写触发同一幂等交卷，按最后已确认草稿结算。客户端断网不暂停考试，截止后到达的草稿拒绝，不相信客户端填写的作答时间。交卷和草稿并发对同一 attempt 串行处理。
- 本地保存未同步草稿（按 userId+attemptId 隔离），离线横幅显示最后确认时间。恢复时拉服务端版本，只有仍在进行且未到期才能提交差量；revision 冲突显示两份答案，让用户确认，不静默覆盖。普通练习离线未交卷可继续同步；考试已到期只允许复制未同步文本作学习笔记。
- 一期支持同端刷新/关闭重开，以及换端读取已同步草稿；未同步本地内容不能跨设备恢复。登录退出清除本地个人草稿；开考前明确说明。
- 重复 requestId 返回原响应；不同 requestId 交同一已交卷 attempt 返回原报告引用。报告轮询可看到自评后版本变化，但不能重新判客观题或重复奖励。服务端持久化 pending effects 标记与数据同事务提交，重试投递各消费方按 answerId/attemptId 去重；不能仅依赖进程内事件完成结算。

## 8. 四卡与公式七件套（BR-08）

| 需求 | Web 学习端 | 移动端 | 出口 |
|---|---|---|---|
| 起源/现实原型/能力地图/抽象阶梯 | W06 抽屉、W07 详情四 Tab | S17 四 Tab | 能力地图→现实域专题/应用训练；代表题独立列在四卡之后 |
| 起源/符号表/推导链/条件边界/应用/家族/变形 | W14 七区，窄屏可折叠 | S33 七区纵向折叠 | 推导→subject=formula 的深钻；小练三型选择→标准作答 |
| 公式条件摘要 | 抽屉与详情首屏红条 | 浮层与详情首屏红条 | “完整条件与误用边界”锚点，不以摘要替代完整条件 |

官网可以展示公开摘要，但四卡语义不更名；学习端的符号表至少含符号含义/定义域/单位（无单位明确标无量纲）。空字段显示待补全；有数据必须可达。公式推导路由采用 `/deepdive/formula/:formulaId`，题目使用 `/deepdive/question/:questionId`，避免 id 碰撞；旧题目路由重定向到带类型版本。

## 9. 从官网返回目标（BR-09）

`from` 只记录来源；`intent={targetType,targetId,action,entrySource}` 记录意图，targetType 白名单 node/formula/question/event/path，action 白名单 read/drill/join/start。后端解析 slug 并生成随机 resumeToken（30 分钟有效），只指向本产品已登记资源，不接受任意 URL。解析接口返回显示标题用于注册页提示“完成后继续学习…”。

- 已登录直接校验目标权限后打开；未登录先保存可恢复试做输入至浏览器本地/移动端本地临时存储，再携 token 注册或登录；不把用户答案放 URL。
- 登录后兑换 token 绑定当前账号并取得 resumeId，24 小时可重复读取并返回同一目标，完成目标导航后确认 consumed。不同账号不得读取已绑定 intent。目标解析不创建成绩/报名记录；报名仍需确认比赛规则后由 join 执行。
- 有目标时先返回该资源，测评仅非阻塞提示；选择先测评的用户，在跳过/完成/退出测评时仍回目标。没有目标才按默认计划进首页。恢复本地答案只回填输入，不自动提交。
- token 过期或目标下架不丢弃已填输入，显示原因并提供资源搜索/推荐与复制输入；不静默落首页。分享 URL 仅携公共目标与来源，不携账号私密数据。

## 10. 计划建议而非自动能力降级（BR-10）

plan_task 状态区分 todo/completed/skipped/absent/rescheduled，附 reason、evidenceRef；有客观学习对象的完成只能由服务端关联完成事件确认，复选框仅发起校验；阅读/个人任务可自报完成但不影响能力或竞技奖励。

- 连续 3 个到期日 absent（无参与且未请假）→只建议减少时长/改期，不降能力、不插入强制先修；skipped/rescheduled 与休息日不计该连续序列。
- 最近 7 天同知识点至少 10 条 BR-01 有效证据、正确率<60%→建议复测/补先修；≥80%且最近 3 个有任务日完成→建议加速。少于 10 条只提示证据不足。已确认掌握度按 BR-01，计划建议不能直接改分或撤销解锁。
- 建议以 basePlanRevision 保存 diff（改哪天/哪任务/原因）；apply 需用户确认且版本匹配，冲突 3011 返回新旧差异；手动计划不被静默覆盖。dismiss 后同一证据窗口不再提醒。
- 应用后的 undo 仅在计划版本未再变化且受影响任务无新增学习证据时允许；否则提供新的调整建议，不回滚已发生学习事实。
- 跳过测评的 placement=pending，首次≥10条有效证据仅生成校准建议；用户确认更新推荐起点，不自动覆盖手动任务。入学定级只依据测评覆盖到的领域，不能用一组算术题推断全领域水平。

## 11. 内容覆盖门禁（BR-11）

12 的总量仍为目标，发布前由真实内容清单生成覆盖矩阵：nodeId×difficulty×questionType、eligibleFamilyCount、curatedCount、prerequisites、courseIds、formulaIds/drillTypes、pathNodeIds。内容文件缺失即未验收，不用示例 ID 冒充已生产。

- P4 每个可用格至少 10 个审核客观题族，另有不重叠晋级战题池；测评、Boss、挑战卷不能复用本轮训练已曝光族。发布校验无可用题时显示“内容筹备中”，与用户能力锁定区分。
- 每个有练习门槛的前置节点必须有可访问的教学与练习路径，根节点练习可直接进入；补救练习可重做已解锁前置，不依赖被它锁住的后继。
- 公式三型有多少显示多少；全量三型验收只对声明已完成的小练集执行。MVC 需列出能贯通六路径/三内核的具体资源集合，未覆盖节点可浏览但标筹备中。
- 所有节点至少两条到达路径是发布覆盖目标；不能用总题量替代，管理端 coverage 校验输出不足清单后补内容或撤下可用声明。
