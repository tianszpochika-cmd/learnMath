## 1. 定位与设计原则

> 官网 = **产品灵魂的第一眼** + **搜索流量的着陆场**。
> 3 秒内让人明白"这数学平台会讲清楚为什么"，30 秒内给出去处（注册 / 下载）。

| 原则 | 落地 |
|------|------|
| 灵魂前置 | Hero 与首屏三模块直接演示推理链/四卡/公式馆，不写空口号 |
| 双轮驱动 | 每个页面同时服务"转化"与"检索"（模块里既有 CTA 也有语义化正文） |
| 数字真实 | 题量/公式数/覆盖域取自 12 号计划的真实数字（上线集 3,000 题/4 域/600 公式），不虚报 |
| 可降级 | AI 相关宣传只展示能力截图/动图，不依赖运行时 LLM |
| 与学习端同源 | 主题色同 `#2F6BFF`，文案常量走 `shared/locales`；品牌名已定稿 **数源 MathOrigin**（G1 ✅） |

## 3. 站点结构（终表 · 在 05 §1.3 基础上定稿）

```
/                       首页（§4.1 九模块）
/paths                  六路径总览（对比表 + 各自 CTA）
/paths/:slug            单路径详情 ×6（SEO 长尾主力页型）
/features               功能亮点（与三内核一一对应）
/download               下载中心（H5 直达 + 三小程序码 + App 指引）
/blog                   博客列表（分类/标签）
/blog/:slug             文章详情（SSR 正文 + 内链 + 文末 CTA）
/about                  关于/理念（学习内核三段论）/联系/备案
/legal/:type            隐私政策 / 用户协议（article type=legal）
404 / 500               品牌化错误页（回首页/搜索入口）
```

- 数据源全部 = app-api 公开接口（`/articles`、`/legal/*`、012 号数字接口见 §9）；
- **无试玩组件（G4）**：所有 CTA 指向 `/register`（学习端）或 `/download`。

### 4.2 `/paths/:slug` 模板（×6 页型统一）

```
H1 路径名 + 一句定位（含关键词）
① 为什么需要这条路径（痛点叙事，200-400 字语义正文）
② 适合谁 / 不适合谁（对号入座，降低跳出）
③ 怎么走（3 步图解：入口→过程→结果）
④ 真实界面（截图/录屏 2-3 张，标注核心交互）
⑤ 常见问题 FAQ（结构化数据 FAQPage JSON-LD）
⑥ CTA 块：[开始这条路径] → /register?from=paths/{slug}
⑦ 相关文章 2 篇（内链）
```

slug 定稿：`course / graph / plan / ladder / special / challenge`（对应 P1/P2/P3/P4/P5/P6）。

### 4.3 `/features` 页面锚点

`#paths` 六路径详解 ｜ `#deepdive` 深钻五玩图解 ｜ `#graph` 知识图谱 ｜ `#wrongbook` 断链错题 ｜ `#ai` AI 导师 ｜ `#formula` 公式馆 ｜ `#community` 社区 ｜ `#gamification` 激励 —— 每锚点 = 演示图 + 3-5 行语义正文 + CTA。

## 5. 视觉与 Hero 概念（G3）

### 5.1 与学习端的关系

- 同源色板：主色 `#2F6BFF`、点缀 `#FFB020`、语义四色沿用 05 §5；
- 官网更"品牌化"：大留白、超大标题（clamp 40-72px）、背景细网格 + 数学元素纹理（坐标纸质感）；
- 字体：标题/正文同学习端系统栈，公式区 KaTeX（与站内一致所见即所得）。

### 5.2 Hero 推理链动图规格

```
背景层：SVG 画布，一道真实题（示例：河宽测量/求根公式推导）
动画：6-8s 循环 —— 条件高亮 → 第1步划出 → warrant 标签浮现("正弦定理")
      → 第2步 → motive 标签("看信号:角+边组合") → 第3步 → 结论框亮 + 绿色对勾
细节：节点连线用描边动画；标签字体小一号、半透明；
      主文案始终浮于动图之上（对比度 ≥ 4.5:1）
性能：Lottie/SVG 手写二选一，首屏不阻塞文本渲染（动图延迟加载）
降级：prefers-reduced-motion / 移动端 → 静态三步图；4G 下首屏 <1.8s
指标：LCP < 1.8s、动图资源 < 200KB
```

### 6.1 关键词簇（首批 40 词目标）

| 簇 | 示例词 | 承载页 | 弹药来源 |
|----|--------|--------|---------|

| 概念动机 | 三角函数为什么存在、为什么要学导数 | /blog + 未来概念词条页 | **四卡内容改写** |
| 公式工具 | 勾股定理推导、求根公式怎么来、公式大全 | /blog + 公式馆(登录页可引流) | **公式 origin/推导改写** |
| 解题方法 | 二次函数解题思路、应用题怎么找等量关系 | /blog | 推理链 motive 改写 |
| 品牌 | {G1 品牌名}、learnMath | / | — |

### 6.2 技术规范

| 项 | 规范 |
|----|------|
| title 模板 | 首页：`{品牌} — {主张}｜推理式数学学习平台`；路径页：`{路径名}｜{一句话定位}-{品牌}`；博客：`{文章标题}-{品牌}` |
| description | 各页型 120-160 字模板，含主关键词与 CTA 词 |
| JSON-LD | WebSite（首页+搜索）、Breadcrumb（全内页）、FAQPage（路径页 FAQ）、Article（博客） |
| sitemap | 每次构建生成：8 骨架页 + 6 路径页 + 全部已发布文章；lastmod 取 published_at |
| robots | 允许全部；屏蔽 /register?from= 参数页重复 |
| 内链矩阵 | 博客 → 路径页（锚文本含关键词）→ 页尾 CTA；页脚全站骨架链接 |
| OG/分享 | 每页 og:title/desc/image（博客取封面，路径页取专属分享图） |
| 预算 | 核心页 Lighthouse SEO ≥ 95、性能 ≥ 90 |

### 6.3 内容-SEO 复用（核心杠杆）

```
四卡(起源/现实) ──改写──►「为什么存在XX」概念动机文
公式 origin+推导 ──改写──►「XX公式怎么来/怎么证」公式文
推理链 motive   ──改写──►「XX题的三种思路」方法文
一次生产 → 学员端内核 + 官网 SEO 双产出（12 §10 管道）
```

## 7. 获客链 L0（G4 无试玩版 · 同步至 09）

```
流量落地（搜索词/分享/投放） → 首页或路径页/文章着陆
 → 灵魂模块建立认知（Hero 动图 / 三内核演示 / 语义正文）
 → CTA 双出口：
     ① [免费开始] → 学习端 /register（带协议勾选，接 L1 冷启动，from 参数归因）
     ② [下载] → /download → H5 直达或扫码 → uniapp 注册（接 L1）
归因：from=paths/course|blog/{slug}|hero|download 全链带参，注册转化入统计
⚠ 二期观察项（G4 暂不做）：免注册试玩组件 —— 若落地页跳出 >70% 再评估
优化回路：着陆页停留/滚动深度/CTA 点击/注册转化 四点漏斗，周复盘改文案（A/B 预留 Hero 主张两版）
```

## 9. 技术与工程（对接 08/04）

- Nuxt 3.21 SSR（Nitro，**S1 基线=cloudstudy official-site 同版，运行于 Node 20.19.5**），文章构建期预取 + 运行时增量（ISR 思路：published_at 变更 → 预览重建或请求时 revalidate）；
- 接口：`GET /articles*`、`GET /legal/{type}`（04 §4.15，均 ◎ 公开）；数字背书模块读 12 号口径接口（`GET /stats/public`，**M 期补**：公开聚合题量/公式数/域数，不泄漏运营敏感数据）；
- 环境变量：`NUXT_PUBLIC_API_BASE`；官网构建产物 = Nitro `.output`（node 服务）+ 静态资源 nginx 直出（08 §4.2 对齐）；
- 中文 SSR 编码 UTF-8、时区 Asia/Shanghai（发布日期渲染）。
